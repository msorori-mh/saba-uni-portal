## Status

## Why LONGRUN-12 was invalidated

LONGRUN-12 relied on `scripts/b1-rpc-principal-harness-01/local-operator-simulation/build-schema-sql.ts` to generate `00-canonical-b1-schema.sql`. That generator rewrote repository migrations in-memory (`SEMANTIC_MIGRATION_REWRITE`) and injected test fixtures, including `request_types.student_visible` mutations. The independent LONGRUN-13 review found:

1. Incoherent `SET ROLE authenticated` inside a session authenticated as `b1_matrix_operator`.
2. The 267-case runner did not prove actual authorization execution under the operator principal.
3. The generated canonical schema was not semantically equivalent to production because migrations were rewritten.
4. Role cleanup used `DROP OWNED BY b1_matrix_operator`.
5. Observation used `FOR SELECT TO b1_matrix_operator USING (true)` across 23 RLS tables.
6. Reproducibility depended on a tracked self-mutating artifact.

All of those are replaced in LONGRUN-14.

## New design principles

- Source migrations are **read-only**. No transformation is applied to any file under `supabase/migrations/`.
- We do **not** claim that replaying 280 migrations byte-for-byte yields the production schema. We instead build a **canonical B1 execution fixture** from exact current object definitions and prove function semantic equivalence via the existing `TARGET-MANIFEST.json` function hashes.
- Actor identity is **JWT-driven, not role-driven**. The 36 canonical functions derive identity only from `auth.uid()`, which reads `request.jwt.claims->>'sub'`. We execute as `b1_matrix_operator` and set the GUC; no `SET ROLE authenticated` is used.
- Observation is performed by **narrow ephemeral SECURITY DEFINER observer functions**, not broad `USING (true)` policies.
- Role lifecycle is fail-closed: role must be **absent** before provision; cleanup is explicit; `DROP OWNED` is not used.
- The 267 harness emits structured evidence and deterministic counters.

## Two-plane architecture

PLANE 1 — Business RPC invocation:
- Connect as `b1_matrix_operator`.
- Inside each case transaction: `SET LOCAL request.jwt.claims = '{"sub":"...","role":"authenticated"}'`.
- Call `act_on_b1_student_request_step_atomic(...)` or `record_external_university_payment_confirmation(...)`.
- Expect a denial from the real authorization branch.

PLANE 2 — Read-only observation/fingerprinting:
- A separate ephemeral observer role owns SECURITY DEFINER functions.
- These functions return only cryptographic fingerprints and counts for TEST_ONLY fixture scope and protected sentinel identifiers.
- The operator role has no direct table SELECT grants on scope relations.

## Canonical B1 fixture

The fixture is generated by `build-canonical-b1-fixture.ts`:
1. Apply `platform-bootstrap.sql` (Supabase-managed prestate: auth/storage/extensions/roles).
2. Apply exact repository migration files **byte-for-byte** up to the pinned migration tip.
3. If replay fails because of irreducible external prestate, the generator aborts and reports the first failing migration.
4. On success, apply Fixture-13.
5. Optionally export a schema-only snapshot for inspection; generated artifacts are gitignored.

Because step 2 is attempted without rewrites, we honestly report `MIGRATION_REPLAY_EQUIVALENCE = NOT_CLAIMED` and rely on independent function-hash attestation.

## Role contract

`b1_matrix_operator`:
- LOGIN (only for the harness to connect)
- NOSUPERUSER, NOBYPASSRLS, NOCREATEDB, NOCREATEROLE, NOREPLICATION, NOINHERIT
- No role memberships
- No table ownership
- No broad SELECT
- EXECUTE only on the two entry RPCs

`b1_matrix_observer`:
- NOLOGIN
- NOSUPERUSER, NOBYPASSRLS, NOCREATEDB, NOCREATEROLE, NOREPLICATION, NOINHERIT
- Owns the observer functions
- Has no direct table grants
