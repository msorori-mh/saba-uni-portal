**السبب الجذري:** مزوّد الإنترنت في اليمن (أو جدار حماية الشبكة) يحجب **خوادم Lovable** على عنوان IP `185.158.133.1` ونطاق `lovable.app`. كل من النطاق المخصص والرابط الاحتياطي يشيران إلى نفس البنية التحتية، لذلك كلاهما محجوب.

هذه ليست مشكلة في الكود أو النشر — هي مشكلة شبكة على مستوى مزوّد الخدمة.

## الحل المقترح: تفعيل وضع Cloudflare Proxy للنطاق المخصص

عند تفعيل وضع البروكسي، يتم توجيه حركة المرور عبر شبكة Cloudflare العالمية بدلاً من الاتصال المباشر بخوادم Lovable. شبكة Cloudflare لديها عناوين IP متعددة منتشرة عالمياً، ومن غير المرجح أن تكون محجوبة في اليمن.

### الخطوات (يقوم بها المستخدم — لا تتطلب تغيير كود):

1. **إنشاء حساب Cloudflare مجاني** على https://cloudflare.com
2. **إضافة نطاق quboolye.com** إلى Cloudflare (الخطة المجانية كافية)
3. **تحديث Name Servers** عند مسجل النطاق (godaddy/namecheap/إلخ) إلى Name Servers الخاصة بـ Cloudflare
4. **في إعدادات المشروع على Lovable:**
   - حذف ربط `quboolye.com` الحالي
   - إعادة ربطه مع تفعيل خيار **"Domain uses Cloudflare or a similar proxy"** ضمن قسم Advanced
5. **في Cloudflare DNS:** تفعيل السحابة البرتقالية (Proxied) على سجلات A و CNAME

### النتيجة المتوقعة:
- زيارات `quboolye.com` ستمر عبر Cloudflare (عناوين IP مختلفة غير محجوبة عادةً)
- يستطيع العميد ومن في نفس الشبكة الوصول للموقع
- مكسب إضافي: تسريع التحميل وحماية DDoS

## خطة بديلة (إن لم يكن Cloudflare ممكناً)

**أ. شراء/ربط نطاق احتياطي ثانٍ** (مثلاً `.org` أو `.net`) وربطه بنفس المشروع. إن كان النطاق الجديد على IP/شبكة مختلفة، قد يعمل.

**ب. للعميد كحل مؤقت فوري:**
- تغيير DNS الجهاز إلى `1.1.1.1` و `1.0.0.1` (Cloudflare)
- أو استخدام VPN خفيف (Cloudflare WARP مجاني وآمن)
- المحاولة من بيانات الجوال بدلاً من شبكة الواي فاي
