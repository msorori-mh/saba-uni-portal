## التشخيص

تحققتُ على مستوى قاعدة البيانات:
- الحسابات موجودة ومؤكّدة (`email_confirmed_at` صحيح).
- البروفايلات والأدوار صحيحة (`faculty_member` و `registrar`).
- `must_change_password = false` لكلا الحسابين.
- **اختبرتُ مباشرة `demo-fac@faculty.usr.edu.ye / Demo@2024` عبر Supabase Auth API → نجح وأعاد access_token.**
- سجلات Auth تُظهر تسجيل دخول ناجح (200) لكلا الحسابين قبل دقائق، ومحاولات فاشلة (400 invalid_credentials) من IP مختلف (209.198.132.53) — أي أن المستخدم يكتب كلمة المرور خطأً يدوياً.

**الخلاصة:** البيانات صحيحة فعلياً، والمشكلة في تجربة الكتابة اليدوية: كلمة المرور `Demo@2024` تحتوي على حرف كبير ورمز `@` يصعب إدخاله على بعض لوحات المفاتيح (خاصة العربية على الجوال)، والمستخدم لا يستخدم زر "تعبئة تلقائية" أو لا يلاحظه.

## الإصلاحات المقترحة في `src/routes/portal-login.tsx`

### 1. تعبئة تلقائية فورية عند فتح بطاقة DEMO (بدون الضغط على زر)
عند فتح صفحة الدخول لأي بوابة (faculty/staff/student) وكانت الحقول فارغة، تُملأ تلقائياً ببيانات DEMO. المستخدم يضغط "دخول" فقط.

### 2. أزرار "نسخ" بجانب المعرّف وكلمة المرور
لكل من المعرّف وكلمة المرور، إضافة أيقونة نسخ إلى الحافظة (`navigator.clipboard.writeText`) مع toast تأكيد. يتجاوز مشكلة الكتابة اليدوية.

### 3. تكبير زر "تعبئة تلقائية" وجعله أكثر بروزاً
رفعه إلى أعلى البطاقة بلون gold مميز بدل اللون الخافت الحالي، مع نص أوضح مثل: "تعبئة البيانات والدخول السريع".

### 4. (اختياري) زر "دخول تجريبي بنقرة واحدة"
زر إضافي يقوم بالتعبئة + الإرسال مباشرة دون الحاجة لضغطتين.

### 5. تحسين رسالة الخطأ
عند ظهور `Invalid login credentials` تُعرض رسالة:
> "البيانات غير صحيحة. إذا كنت تستخدم الحساب التجريبي، اضغط زر **تعبئة تلقائية** بالأسفل."
