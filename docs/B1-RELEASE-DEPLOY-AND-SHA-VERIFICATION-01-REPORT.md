`preview_ui--publish` deploys the workspace HEAD, not an arbitrary ref. The
workspace HEAD is currently `74e603d`, one commit ahead of the requested
`90914ab`. That extra commit is an auto-generated route-tree regeneration
only, but its SHA does **not** equal the mandated release SHA.

Per the authorization envelope:

> بعد النشر: يجب أن يطابق `90914abf…`؛ إذا لم يتطابق، توقف بقرار HOLD ولا تطبق
> أي شيء آخر.

Publishing now would produce a deployed artifact whose SHA cannot match
`90914ab24af61be0333d9ddb95f8ae513f7da62c`. Rewinding `HEAD` back onto
`origin/main` requires a stateful git operation (`reset`/`checkout`) which is
explicitly disallowed by the agent contract. Therefore the deploy step is
blocked before it starts — no publish call was made.
