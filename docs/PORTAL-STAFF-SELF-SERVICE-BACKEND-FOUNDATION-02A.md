# PORTAL-STAFF-SELF-SERVICE-BACKEND-FOUNDATION-02A

## القرار التنفيذي

هذه الحزمة تبدأ المرحلة الثانية بخلفية مصدرية معزولة، ولا تطبق أي ترحيل على Supabase أو الإنتاج. واجهات المرحلة الأولى تبقى عاملة ببيانات العرض إلى أن تُغلق بوابة التطبيق والربط.

## النطاق المنجز

- نموذج أدوار مستقل: `Employee / Direct Manager / HR / Finance / Administrator` دون توسيع `app_role` القديم.
- طلبات موحدة بعشرة أنواع خدمة ومسارات اعتماد ثابتة.
- إرسال واعتماد/رفض ذري عبر RPC مع `idempotency_key`.
- منع اعتماد الموظف لطلبه، وإلزام سبب الرفض.
- سجل أحداث غير قابل للتعديل أو الحذف.
- نماذج أرصدة الإجازات، الرواتب ومكوناتها، المسار الوظيفي، المراسلات، العهد، المرفقات وصندوق الإشعارات.
- حقول مصدر القراءة الآمنة من أنظمة الموارد البشرية والمالية والعهد.
- RLS لجميع جداول الحزمة؛ العميل لا يملك INSERT أو DELETE مباشرًا.
- سرية الرواتب: الموظف يقرأ صفوفه فقط، وFinance/Administrator يقرآنها بصلاحية مخصصة؛ Direct Manager وHR لا يحصلان على صلاحية رواتب.
- عقد TypeScript/Zod موحد للتحقق من النماذج ومصفوفة الصلاحيات.

## مسارات الاعتماد

| الخدمة | المسار |
|---|---|
| الإجازة، المغادرة | المسؤول المباشر ← الموارد البشرية |
| نقل/إرجاع العهدة | المسؤول المباشر ← الموارد البشرية |
| إفادة وظيفية، شهادة خبرة | الموارد البشرية |
| العمل الإضافي | المسؤول المباشر ← الموارد البشرية ← المالية |
| التدريب | المسؤول المباشر ← الموارد البشرية |
| الترقية والتسوية | المسؤول المباشر ← الموارد البشرية |
| إخلاء الطرف | المسؤول المباشر ← الموارد البشرية ← المالية ← Administrator |

## ضوابط البيانات

- البيانات الحساسة لا تُقرأ إلا عبر RLS.
- جداول التشغيل للعميل قراءة فقط؛ الكتابة التشغيلية عبر دوال ذرية محددة.
- المرفقات تقبل PDF/JPEG/PNG فقط، حتى 10MB، مع SHA-256 وحالة فحص.
- مسار التخزين الخاص `staff-service-private` عقد ثابت؛ إنشاء bucket وسياسات `storage.objects` والتوقيع المؤقت ضمن دفعة الربط التالية.
- صندوق الإشعارات يفصل إنشاء الحدث عن الإرسال الفعلي للبريد والجوال ويتيح retry آمنًا.
- الحقول `source_system/source_reference` مخصصة للقراءة من الأنظمة القائمة؛ لا تحاول الحزمة استبدالها.

## حدود هذه الدفعة

- لا تطبيق migration على staging أو production.
- لا بيانات حقيقية ولا حسابات اختبارية.
- لا ربط للواجهات مع الجداول قبل تطبيق migration في بيئة معزولة وتوليد أنواع Supabase.
- لا مفاتيح تكامل أو أسرار أو مزود بريد/جوال.

## بوابة الدفعة التالية

`STAFF_SELF_SERVICE_BACKEND_BINDING_02B`:

1. تطبيق migration في بيئة اختبار معزولة بعد preflight.
2. إنشاء bucket الخاص وسياسات التحميل والتنزيل الموقّع والفحص.
3. توليد أنواع Supabase وربط واجهات الموظف والأدمن تدريجيًا.
4. اختبارات PostgreSQL 17 فعلية لمصفوفة الأدوار، الرفض، replay والتزامن.
5. تكامل قراءة تجريبي مع HR/Finance ببيانات `TEST_ONLY` فقط.
