# STUDY-PLANS-IMPORT-CONTEXT-02 — Scoped Study Plans Import UX + Validation

Project: بوابة كلية تكنولوجيا المعلومات وعلوم الحاسوب — جامعة إقليم سبأ  
Scope: تحسين تجربة استيراد الخطط الدراسية والتحقق فقط، دون migrations أو تعديل بيانات إنتاجية أو تنفيذ import.

## 1. المشكلة التي تم حلها

استيراد `study_plans` كان عاماً ويعتمد على `program_code`, `plan_name`, `version`, `level`, `semester` داخل ملف Excel فقط. هذا يسمح بأخطاء ربط البرنامج، ولا يطلب اختيار القسم أو البرنامج من الشاشة، ويعطي رسائل غير دقيقة عند قيم خاصة مثل `All` أو placeholder مثل `IT4XX(E)`.

أضيفت الآن بطاقة إلزامية داخل `/admin/imports` عند اختيار `study_plans` باسم:

`إعداد سياق الخطة الدراسية`

وتفرض تحديد:

- القسم.
- البرنامج المفلتر حسب القسم.
- اسم الخطة.
- الإصدار.
- حالة الخطة.
- نوع الاستيراد:
  - `full_plan`
  - `single_semester`
- الفصل عند `single_semester`.

## 2. الملفات المعدلة

| الملف | سبب التعديل |

لا.

لا توجد schema changes في هذه المرحلة.

## 4. كيف أصبح الاستيراد مرتبطاً بالقسم والبرنامج

تمت إضافة server function قراءة فقط:

`getStudyPlanImportContextOptions`

تعيد:

- الأقسام.
- البرامج.
- المستويات.
- السنوات.
- الفصول.
- الخطط الموجودة.

في الواجهة:

- يختار المستخدم القسم أولاً.
- البرامج تُفلتر حسب `department_id`.
- البرنامج المختار من الشاشة هو المصدر الأساسي.
- عند رفع الملف، يتم حقن `program_code` من البرنامج المختار.
- إذا احتوى الملف `program_code` مختلفاً، يتم إيقاف المعاينة برسالة:
  `البرنامج داخل الملف لا يطابق البرنامج المختار من الشاشة.`

## 5. التعامل مع `department_id` بدلاً من `department_code`

بما أن جدول `departments` لا يحتوي `code`، فإن السياق يستخدم:

- `departmentId` داخلياً.
- `name_ar` للعرض فقط.

لم تتم إضافة `department_code` إلى قالب الخطط، ولم يتم الاعتماد عليه.

## 6. التعامل مع الفصل الدراسي

تم دعم نمطين:

### `full_plan`

- الملف يجب أن يحتوي `level` و`semester` في كل صف.
- لا يتم حقن فصل واحد من الشاشة.
- مناسب لاستيراد خطة كاملة متعددة المستويات والفصول.

### `single_semester`

- الشاشة تتطلب `semesterCode`.
- إذا كان الصف يحتوي `semester` يجب أن يطابق الفصل المختار.
- إذا كان الصف لا يحتوي `semester` يتم حقن الفصل المختار لكل الصفوف.
- أي تعارض يوقف المعاينة برسالة عربية واضحة.

## 7. دعم `full_plan` و`single_semester`

يتم حفظ `importMode` في سياق الواجهة، ثم يرسل إلى:

- preview validation
- run import

ويستخدم في:

- تحضير الصفوف client-side.
- إعادة تحضير الصفوف server-side عند preview/run لمنع bypass.

## 8. التعامل مع `All`

في `validateStudyPlans`:

- إذا كانت `prerequisite_course_code = All`، تظهر رسالة:
  `القيمة All ليست كود مقرر؛ ضعها في الملاحظات.`
- لا يتم التعامل معها كـ course code.
- لا يتم إنشاء متطلب سابق.

## 9. التعامل مع `IT4XX(E)`

في `course_code` أو `prerequisite_course_code`:

تظهر رسالة:

`IT4XX(E) يبدو مقرراً اختيارياً عاماً وليس كود مقرر فعلياً؛ يجب تحديد مقرر اختياري فعلي أو إضافته كمرجع معتمد.`

ولا يتم قبولها ككود مقرر إلا إذا صُمم لاحقاً نموذج رسمي للمقررات الاختيارية.

## 10. عرض المقررات والمتطلبات السابقة الناقصة

عند ظهور أخطاء preview في `course_code` أو `prerequisite_course_code`:

- تظهر قائمة `المقررات غير الموجودة`.
- تظهر قائمة `المتطلبات السابقة غير الموجودة/غير الصالحة`.

القائمة تُعرض أعلى preview بجانب ملخص السياق:

- القسم.
- البرنامج.
- اسم الخطة.
- الإصدار.
- نوع الاستيراد.
- الفصل.
- إجمالي الصفوف.
- الصفوف الصالحة.
- الصفوف ذات الأخطاء.

## 11. التعامل مع خطة موجودة

إذا وجدت خطة لنفس:

- `program_id`
- `version`

يتم منع المعاينة/التنفيذ برسالة:

`توجد خطة مسبقاً لهذا البرنامج والإصدار.`

لا يوجد replace صامت، ولا حذف مقررات خطة، ولا استبدال ضمن هذه المرحلة.

## 12. هل تأثرت مستوردات أخرى؟

التعديلات محصورة في `study_plans` باستثناء قراءة الخيارات وقوالب التعليمات. مستوردات الطلاب والأقسام والبرامج والمستويات والمقررات لم تتغير وظيفياً.

- المقررات.

## 16. ملاحظات وقيود

- لا يوجد حقل `notes` في `study_plan_courses` حالياً، لذلك لم يتم دعم حفظ ملاحظات مثل "يتطلب إكمال جميع مقررات الخطة السابقة".

- لا تزال المقررات الناقصة مثل `IT323` و`IT333` بحاجة إلى تعريف رسمي قبل استيراد خطة IT كاملة.
