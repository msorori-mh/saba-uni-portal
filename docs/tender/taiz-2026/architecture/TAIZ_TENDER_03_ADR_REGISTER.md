## 2. تفاصيل القرارات المعمارية الرئيسية

### ADR-01: نمط المعمارية الموحدة (Modular Monolith)
- **السياق (Context):** تشترط كراسة المناقصة (ص 6، 25) معمارية مرنة عالية الأداء تدعم 5,000 إلى 25,000 مستخدم وتستضاف محلياً وتكون قابلة للتطور المستقبلي.
- **القرار (Decision):** بناء النظام بنمط **Modular Monolith** موزع إلى 14 موديولاً واضح الحدود مع استقلالية تامة لجداول البيانات والتواصل الداخلي عبر الأحداث والعقود.
- **البدائل المدروسة:** (1) Microservices مشتتة (تم استبعادها بسبب تعقيد التشغيل واستهلاك الموارد الزائد في البيئة المحلية)، (2) Monolith تقليدي غير منظم (تم استبعاده لصعوبة الصيانة).
- **الآثار والنتائج (Consequences):** أداء فائق (<300ms)، سهولة النشر والصيانة، وإمكانية فصل أي موديول إلى Microservice مستقبلاً بمرونة تامة.

### ADR-02: استراتيجية تعدد المستأجرين (Multi-Tenancy) للمواقع الـ 25
- **السياق:** حاجة الجامعة لإدارة الموقع الرئيسي و 25 موقعاً فرعياً للكليات عبر نطاقات فرعية مستقلة مع الحوكمة المركزية واستقلالية النشر لكل كلية.
- **القرار:** استخدام معمارية **Single Codebase Multi-Tenant** مع قاعدة بيانات موحدة مفلترة بعمود `site_id` وسياسات PostgreSQL RLS، وتوجيه النطاقات الفرعية آلياً عبر Host Header.
- **البدائل المدروسة:** (1) إنشاء 25 قاعدة بيانات منفصلة (استبعدت لصعوبة الصيانة والتحديثات)، (2) إنشاء 25 مشروع ووردبريس مستقل (استبعدت لانهيار الحوكمة والأمن).

### ADR-03: توحيد الهوية والمصادقة عبر Keycloak و OIDC
- **السياق:** توفير تجربة دخول موحد (Single Sign-On) لكافة البوابات مع فرض MFA للأكاديميين والإداريين وتكامل محتمل مع أنظمة الجامعة القائمة.
- **القرار:** دمج خادم **Keycloak** مفتوح المصدر الداعم لمعايير OpenID Connect و SAML 2.0، مع ربطه بقواعد بيانات المستخدمين وتفعيل بروتوكولات TOTP/SMS للـ MFA.
- **البدائل المدروسة:** (1) بناء نظام مصادقة مخصص من الصفر (استبعد لارتفاع المخاطر الأمنية)، (2) الاعتماد على خدمات سحابية مثل Auth0 (استبعد لمخالفته مبدأ الاستضافة المحلية السيادية).

### ADR-04: بوابة الواجهات المركزية ونمط مكافحة الفساد (API Gateway & ACL)
- **السياق:** الحاجة للربط الآمن للقراءة والعرض مع أنظمة قديمة (SIS/HR/Finance) مع حماية المنظومة من بطء أو انهيار الأنظمة القديمة.
- **القرار:** تطبيق بوابة **Kong / Envoy API Gateway** مع طبقة **Anti-Corruption Layer (ACL)** وقواطع الدائرة (Circuit Breakers) وتحديد معدلات الطلب.
- **الآثار:** عزل النواة الجديدة عن تشوهات النظم القديمة وضمان استقرار البوابات حتى في حال توقف النظام القديم.

### ADR-05: محرك الذكاء الاصطناعي السيادي المحلي 100% On-Premises
- **السياق:** الكراسة تشترط مساعداً ذكياً يستند إلى تقنية RAG مع حظر إرسال بيانات الجامعة لأي سحابة خارجية وضمان خلو الإجابات من الهلوسة.
- **القرار:** استضافة نماذج مفتوحة المصدر محلياً (Llama 3.1 / Qwen 2.5) مع قاعدة بيانات متجهية (Qdrant)، ومكتبة Farasa للمعالجة الصرفية العربية، وسياسة امتناع صارمة عند ضعف الأدلة (<0.75).
- **الآثار:** ضمان السيادة الرقمية التامة وحماية سرية بيانات الطلاب واللوائح بنسبة 100%.
