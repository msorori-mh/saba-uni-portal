# PORTAL_STAFF_SELF_SERVICE_GOVERNANCE_02F

مرحلة مصدرية مغلقة افتراضياً لبوابة موظفي كلية تكنولوجيا المعلومات وعلوم
الحاسوب. لا تدّعي هذه المرحلة تطبيق الهجرة أو تفعيل التكاملات أو النشر.

## النطاق

- تقارير مجمعة للإجازات، الحضور، العمل الإضافي، التدريب، الأداء، الترقيات،
  العهد وإخلاء الطرف.
- نطاق المدير المباشر يقتصر على الأقسام المعيّن عليها فعلياً. HR وAdministrator
  يملكان نطاق المؤسسة، ولا يحصل Finance أو Employee أو outsider على التقرير.
- تكامل قراءة فقط مع HR وFinance عبر لقطات منظمة تحمل المصدر ووقت المزامنة؛
  لا توجد أعمدة لأسرار الاتصال أو endpoints أو tokens أو payload عام.
- إدخال اللقطات محصور في service_role، ولا توجد كتابة عكسية إلى الأنظمة
  القائمة.
- AAL2 مطلوب من الخادم قبل التقارير، التصدير، مراقبة التكامل وسجل التدقيق.
- قراءة موحدة مختزلة لسجلات 02A/02D/02E/02F دون metadata أو أسباب حرة أو
  مسارات أو رموز تحقق أو قيم رواتب.

## الواجهات

- StaffGovernanceEmployeePanel: حالة MFA ومصدر بيانات الموظف فقط.
- StaffGovernanceAdminPanel: التقرير المصرح، سلامة التكاملات، والتدقيق
  المختزل.
- المكونات RTL وتستخدم المحول
  src/lib/staff-self-service-governance.ts فقط.
- العلم staffSelfServiceGovernance يظل false حتى اجتياز staging.

## ضوابط البيانات

الجداول staff_hr_read_snapshots وstaff_finance_read_snapshots إسقاطات
قراءة وليست بديلاً للنظامين. لا يحصل authenticated أو anon على أي صلاحية
جدولية عليهما. تعرض RPCs العامة للموظف المصدر ووقت آخر مزامنة فقط، ولا تعرض
external_record_id.

سجل staff_governance_audit_events append-only باستخدام مشغل الرفض الموروث
من 02A. لا يقبل السجل metadata حرة أصلاً، وتوثق عمليات عرض/تصدير التقرير
وعرض سلامة التكامل والتدقيق الموحد.

## التحقق

- عقد مصدر يثبت MFA، النطاق، غياب أسرار التكامل، المحول RPC-only، RTL والعلم
  المغلق.
- verifier معاملاتي PostgreSQL 17:
  tests/staff-self-service/pg17/40-verifier-02f.sql.
- مصفوفة الاختبار تشمل Employee / Direct Manager / HR / Finance /
  Administrator / outsider وAAL1/AAL2 وservice_role.
- لا تسجل هذه الوثيقة PASS قبل نجاح Web CI على commit المرحلة.

## خطة التطبيق والاستعادة

التطبيق المستقبلي منفصل إلى Preflight ثم Apply ثم Post-verify. يجب أولاً
التأكد من وجود 02A/02B/02D/02E، وأخذ جرد الجداول والدوال والسياسات والمنح،
ثم تطبيق الهجرة وتشغيل verifier لكل الأدوار قبل تفعيل العلم.

الهجرة forward-only. عند الحاجة إلى استعادة تشغيلية بعد التطبيق يبقى العلم
false، وتسحب منح EXECUTE عن RPCs الستة العامة، وتتوقف مهمة ingestion، ثم
تُحفظ snapshots وسجلات التدقيق للامتثال ولا تُحذف. أي إسقاط لاحق للجداول
يتطلب نافذة تغيير مستقلة وموافقة احتفاظ بيانات.
