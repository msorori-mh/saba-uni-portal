2. 15-STEP EXECUTABLE E2E VERIFICATION CYCLE
---------------------------------------------

STEP C2.1: STUDENT VISIBILITY IN CATALOG
  Action: Query `request_types` where `code = 'excused_absence'`.
  Assertion: `student_visible = true` AND `is_active = true`.

STEP C2.2: STUDENT DYNAMIC FORM RENDER
  Action: Load request creation interface `/student/requests/new?type=excused_absence`.
  Assertion: Form renders fields: `absence_type` (exam/lectures), `course_id` (lookup), `absence_date` (date picker), `medical_report` (file upload).

STEP C2.3: REFERENCE OPTIONS LOOKUP
  Action: Query student enrolled courses reference endpoint `get_student_enrolled_courses()`.
  Assertion: Returns active course enrollment records for current semester.

STEP C2.4: DRAFT / AUTOSAVE LIFECYCLE
  Action: Call `save_request_draft` RPC with form payload.
  Assertion: Returns `draft_id`, status = `draft`, request payload preserved.

STEP C2.5: ATTACHMENTS UPLOAD & SIGNED URL
  Action: Request upload URL via `create_attachment_upload_url`.
  Assertion: Returns Signed Upload URL targeting private bucket `request-attachments/excused-absence/`.
  Verify: Upload medical/excuse document -> Content-Type verified.

STEP C2.6: ATOMIC SUBMISSION
  Action: Call `submit_student_request(draft_id)`.
  Assertion: Request status transitions from `draft` to `pending_processing`.

STEP C2.7: CURRENT WORKFLOW STEP RESOLUTION
  Action: Query `student_requests` for submitted request.
  Assertion: `current_step = 1`, `processing_unit = 'department_head'`.

STEP C2.8: CORRECT PROCESSOR INBOX RESOLUTION
  Action: Login as assigned Department Head -> Query `/staff/inbox`.
  Assertion: Request listed in Department Head inbox for course's department.

STEP C2.9: NEGATIVE AUTHORIZATION TEST (WRONG ROLE REJECTION)
  Action: Attempt `process_request_step` RPC as unassigned role.
  Assertion: RPC REJECTS call with error `42501` / `FORBIDDEN`.

STEP C2.10: POSITIVE AUTHORIZATION TEST (CORRECT ROLE STEP APPROVAL)
  Action: Execute `process_request_step` RPC as assigned `department_head`.
  Assertion: Step 1 completes -> Request advances to Academic Affairs / Registrar.

STEP C2.11: DECISION LOGIC (FINAL APPROVAL)
  Action: Process Step 2 approval.
  Assertion: Request status becomes `approved`.

STEP C2.12: ACADEMIC EFFECT EXECUTION
  Action: Post-approval execution handler records excuse record.
  Assertion: Course attendance / exam excuse entry created for student in course section.

STEP C2.13: STUDENT STATUS TRANSITION
  Action: Query student excuse record.
  Assertion: Absence marked as `excused` for target course & date.

STEP C2.14: NOTIFICATION EMISSION
  Action: Query `notifications` for student user ID.
  Assertion: Notification inserted: "تم قبول عذر الغياب".

STEP C2.15: HISTORY & AUDIT TRAIL
  Action: Query `request_history` for request ID.
  Assertion: Full step history recorded with timestamps and processor UUIDs.

3. PASS CRITERIA
----------------
1. All 15 verification steps complete without errors.
2. Wrong role access strictly rejected.
3. Course excuse recorded in academic records.
4. Complete audit trail recorded in request_history.
