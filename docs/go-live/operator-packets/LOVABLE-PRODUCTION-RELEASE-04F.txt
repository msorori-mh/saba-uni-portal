1. SCOPE AND NON-AUTHORIZATION
------------------------------
This packet prepares one deterministic production release through the existing
Lovable production channel. It does not authorize a build, deploy, publish, DNS
change, Supabase write, migration, backend activation, or test-data creation.

Cloudflare Workers in this repository is the isolated staging channel only. It
must not be promoted, routed, or renamed into the production domain.

2. FINAL SOURCE FREEZE
----------------------
After 04F is merged, the operator must set CANDIDATE_SHA to the exact 40-character
SHA currently at origin/main. The pre-merge SOURCE_BASELINE above is evidence of
the starting point, not the deploy candidate.

Read-only checks:
  git fetch origin main
  git rev-parse origin/main
  git status --porcelain

Required evidence:
  - CANDIDATE_SHA is exactly 40 lowercase hexadecimal characters.
  - The checkout is clean and exactly equals origin/main at CANDIDATE_SHA.
  - All required GitHub checks for CANDIDATE_SHA are PASS.
  - Lovable source is synchronized to that exact commit before any build action.
  - The current healthy Lovable deployment/version ID is recorded as
    PREVIOUS_HEALTHY_DEPLOYMENT_ID before changing anything.

If any item is unknown, mismatched, or stale: HOLD_PRODUCTION_RELEASE_04F.

6. POST-PUBLISH READ-ONLY PROOF
-------------------------------
Only after Gate B and the Lovable publish completes, run:

  EXPECTED_BUILD_SHA=<CANDIDATE_SHA> \
    bun run scripts/production/verify-production-release.ts

The verifier performs GET requests only. PASS requires:
  - https://quboolye.com/version.json returns HTTP 200;
  - Cache-Control contains no-store;
  - JSON is exactly {"sha":"<CANDIDATE_SHA>"};
  - root HTML meta[name="build-sha"] equals CANDIDATE_SHA;
  - www.quboolye.com either serves the same SHA or redirects to the canonical host.

Then perform read-only browser smoke for login plus the Admin, Staff, Faculty,
Department Chair, and Student shells. Do not submit forms, send messages, create
requests, mutate data, or bypass authentication during this smoke.

or critical routing verification fails after publish. Re-select or re-publish
PREVIOUS_HEALTHY_DEPLOYMENT_ID through the same Lovable-only single-writer lease,
then re-run the read-only SHA proof against the restored version.

If the rollback target was not recorded before Gate A, deployment is blocked.
