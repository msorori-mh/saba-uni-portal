# PORTAL-STAFF-SELF-SERVICE-STORAGE-BINDING-02B

## الهدف

إغلاق أول بوابة تشغيلية للمرحلة الثانية دون لمس الإنتاج: تطبيق 02A و02B على PostgreSQL 17 مؤقت، إثبات مسارات الصلاحيات، وإنشاء طبقة الربط الحية والتخزين الخاص للمرفقات.

## ما تم تنفيذه

- bucket خاص باسم `staff-service-private`، غير عام، بحد 10MB وأنواع PDF/JPEG/PNG فقط.
- مسارات كائنات مولدة من النظام؛ لا يدخل اسم الملف الذي يرسله المستخدم في المسار.
- upload intent ذري وidempotent، ثم رفع مباشر مقيد بـRLS، ثم finalize يتحقق من وجود الكائن.
- فحص الملفات إلزامي؛ التنزيل ممنوع قبل `scan_state=clean`.
- دالة الفحص متاحة لـ`service_role` فقط وليست للموظف أو الأدمن من المتصفح.
- تنزيل خاص عبر عقد 300 ثانية و`createSignedUrl`، دون أي public URL.
- سياسة INSERT ضيقة للكائن المطابق للموظف والطلب والـintent فقط.
- سياسة SELECT للكائن النظيف فقط ولصاحب الطلب أو المعالج المخول.
- لا سياسات UPDATE/DELETE مباشرة على كائنات bucket.
- طبقة TypeScript واحدة خلف الواجهات للإرسال والقرار والرفع والتنزيل؛ لا كتابة مباشرة إلى جداول الأعمال.
- تصحيح ACL أمامي لدوال RLS المنطقية في 02A حتى يستطيع `authenticated` استدعاء predicates الآمنة دون كشف صفوف.

## إثبات PostgreSQL 17 المعزول

الحزمة تنشئ حاوية PostgreSQL 17 مؤقتة وتنفذ بالتسلسل:

1. مخطط Supabase مصغر لـ`auth` و`storage`.
2. migration 02A كاملة.
3. migration 02B كاملة.
4. verifier داخل `BEGIN/ROLLBACK`.

المصفوفة المثبتة:

- إرسال طلب وإعادة idempotent.
- مسار Direct Manager ثم HR.
- منع اعتماد الموظف لطلبه.
- سبب الرفض إلزامي ومحفوظ.
- منع تعديل وحذف سجل التدقيق.
- الموظف يرى راتبه فقط، والمدير لا يرى الرواتب، وFinance يرى الدفعة.
- منع outsider من رفع كائن.
- منع تنزيل الملف قبل الفحص.
- السماح بالتنزيل الخاص بعد الفحص النظيف.
- عدم وجود منح INSERT/UPDATE على جداول الأعمال للعميل.

## حدود السلطة الحالية

- لا تطبيق على Supabase staging أو production.
- لا secrets ولا مزود فحص ملفات أو بريد أو جوال.
- الواجهات لا تتحول إلى live mode قبل تطبيق migrations وتوليد الأنواع في البيئة المستهدفة.
- لا دمج لـPR #371 أو #372 ضمن هذه الدفعة.
