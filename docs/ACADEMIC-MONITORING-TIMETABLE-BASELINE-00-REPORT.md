تثبيت خط أساس قابل للتدقيق للفصل الحالي قبل تطوير مسارين: (1) المتابعة اليومية والأسبوعية والشهرية لسير المحاضرات ومفردات المقرر؛ (2) نقل نسخة الجدول المنشورة من منصة الجداول إلى البوابة. نطاق التجربة المقترح كلية تكنولوجيا المعلومات وعلوم الحاسوب، برنامج علوم الحاسوب، المستوى الأول والثاني، مع فصل العام والموازي.

**STAGE-00 = PASS_WITH_NOTES (source mapping)**: المخططات وعقود المصدر جُردت. **LIVE_DATA_GATE = HOLD**: لا تتوفر هنا قراءة موثوقة لبيانات الفصل الحالي المنشورة، أو صفوف البوابة المقابلة، أو حسابات الأدوار؛ لذلك عدد الصفوف المتطابقة/المفقودة/المتعارضة `UNKNOWN`، ولم يُرفع جدول أو تقرير رسمي.

### تحويل اليوم ونوع الجلسة

`usrtimetable` يستخدم اليوم `0=الأحد ... 6=السبت` في `src/lib/reports/formatters.ts`. مستورد البوابة يستخدم `sunday ... saturday` نصيًا. التحويل تصريح ثابت في العقد مع اختبار الحدود 0 و6 ورفض خارج 0..6. النوع `lecture/lab/tutorial` يُقابل نظري/عملي/تمارين بعد تحقق مستقل من قيم `session_type` الحية؛ لا تحويل تلقائي لكل نوع غير معروف إلى `lecture`.

## 2. نتائج فحص مسار الاستيراد الحالي

- قالب البوابة `template_class_schedule.xlsx` يطلب `course_code`, `section_code`, `day_of_week`, `start_time`, `end_time`, `room_code`، والرقم الوظيفي اختياري. السنة والفصل والبرنامج والمستوى تُختار من الواجهة ولا تُحفظ في الملف.
- `loadScheduleLookups` يربط المقرر/الشعبة والقاعة والرقم الوظيفي، ثم `validateClassSchedule` يفحص صفوف الملف وتعارضات ذات **الفترة المطابقة بالضبط**. يحتاج عقد المزامنة أيضًا كشف تداخل `[start,end)` الجزئي بين أي فترتين.
- `executeScheduleImport` يستدعي `replace_class_schedule_for_context` ويعيد الإدخال بعد إزالة جدول سياق الشعب. لا يدعم تعقب النسخة المنشورة، مقارنة سابقة/لاحقة، أو أثر تغير الإسناد على سجل التنفيذ. `logScheduleImportResult` منفصل وبصيغة best-effort؛ نجاح الاستيراد لا يضمن سجل تدقيق متزامنًا.
- يملك `admin/system_admin/registrar` حق كتابة الاستيراد بحسب `imports.functions.ts`؛ يجب فصل صلاحية **المعاينة** عن **تفعيل الإصدار** وإعادة اختبار التفويض داخل المعاملة/الدالة نفسها، خصوصًا مع `supabaseAdmin` على الخادم.
- ملف الطباعة الحالي في المنصة ليس صالحًا: `sessionToExportRow` يضع `course_code: ""` ويخرج يومًا عربيًا وفترة مجمعة؛ وقد تظهر الجلسة المشتركة على صفحات متعددة (`countUniqueSessions` تعترف بهذا). يجب إنشاء حزمة تشغيلية جديدة من النسخة المنشورة، لا تعديل تقارير الطباعة لتصبح مصدر حقيقة.

## 3. نتائج فحص مسار المتابعة الحالي

- توجد خطة منشورة لكل `course_section` وجلسات مرقمة و`syllabus_session_id` اختياري، وRPC تسجيل التنفيذ بعضو هيئة التدريس المسند. الحالات الحالية: `executed`, `hindered`, `postponed`, `cancelled`, `compensated`، مع عرض `not_recorded`.
- `cdp_delivery_monitoring` يقبل فقط `week/month/term`، ويحسب `week=current_date-7` و`month=current_date-30`؛ لا يوم، ولا أسبوع/شهر تقويمي مغلق، ولا إسناد تقرير/اعتماد رئيس القسم ثم نائب العميد ثم العميد.
- عقد RPC الحالي يمنح `registrar` و`student_affairs` نطاق الكلية، بينما نائب العميد للشؤون الأكاديمية ممثل وظيفي محدد. يلزم ربط مؤسسي صريح لهذا الدور قبل إضافة صلاحية الاعتماد؛ لا يكفي ظهور زر أو إعادة استخدام دور واسع.
- مصدر المتابعة الحالي جلسات خطة المقرر وتنفيذها؛ ليس له رابط مضمون بهوية موعد منشور وإصداره. نسبة الجلسات المنفذة ليست بذاتها قياس انتظام الجدول أو نسبة المفردات المنفذة فعليًا.
- أدلة أغسطس في `docs/reviews/PORTAL-CDP-DATA-REPAIR-AUDIT-AND-AUTHZ-SCOPE-CLOSURE-01.md` تخص ممثلين تجريبيين وقتها، ولا تثبت بيانات العام الجديد. مخطط الإنتاج الحالي، أعداد الصفوف، وتوافر حسابات أدوار موثقة لا تزال غير مثبتة في هذه المرحلة.

## 4. حزمة القراءة الحية المطلوبة لإغلاق بوابة البيانات

تُنفذ من قناة قراءة مصرح بها على المصدرين، ضمن الفصل والكلية المحددين، مع **أعداد وتجميعات ونسخ/رموز فقط**؛ لا تُنسخ أسماء الطلاب أو بيانات حساسة إلى التقرير. لا يُعد وجود Migration في المصدر دليلًا على تطبيقها:

| مصدر | قياسات يجب التقاطها | النجاح المطلوب |
|---|---|---|
| منصة الجداول | النسخة المنشورة الحالية ومعرفها وحالة إصدارها، الفصل والكلية ونظام الدراسة، عدد `schedule_sessions` الفعالة موزعًا حسب برنامج/مستوى/نوع/دفعة/مجموعة؛ عدد بدون محاضر/قاعة/رمز مقرر؛ بصمة المصدر | نسخة منشورة واحدة مختارة صراحة مع حصيلة جلسات منزوعة التكرار؛ لا استخدام لمسودة أو نسخة مؤرشفة. |
| البوابة | السنة/الفصل الحالي، المقررات والعروض والشعب النشطة، الفصول العامة/الموازية، أعضاء الهيئة بأرقام وظيفية، القاعات برموزها، `class_schedule` الحالي، الخطط المنشورة وسجلات التنفيذ | تغطية المطابقات حسابيًا؛ المفقود أو المكرر أو غير المعتمد يُبلغ برقم واضح ولا يخمن. |
| الهوية والتنظيم | حسابات TEST_ONLY المعتمدة: عضو مسند، رئيس قسم، نائب عميد، عميد، طالب مسجل وغير مسجل | التفويض الحقيقي لكتابة التنفيذ واعتماد التقارير وقراءة نطاق القسم/الكلية يثبت بمصفوفة ALLOW/DENY مباشرة. |
| التقويم | تاريخ الفصل الرسمي، العطل، أيام الدراسة، مهل إغلاق اليوم/الأسبوع/الشهر | توقيع صاحب العملية الأكاديمية على معنى «مقرر» و«منفذ» و«تعويض» والأسبوع الإداري. |

## 5. الحزمة التنفيذية التالية بعد إغلاق الجرد

`TIMETABLE-EXCHANGE-CONTRACT-01`، مسار source-only في فرعين معزولين، يحدد مخطط `manifest + sessions + beneficiaries` ذا نسخة، وقواعد الربط والتكرار والتوقيت، وتوليد حزمة من نسخة منشورة فقط، ومتحقق Dry Run في البوابة بلا كتابة. معايير النجاح: 0 ربط تخميني، 0 حذف/استبدال خلال المعاينة، تطابق عدد الجلسات الفعلية، رفض إصدار غير منشور أو قديم أو معدّل، وفحص جلسة مشتركة والعام/الموازي وتداخل الفترات. تفعيل الإنتاج خطوة منفصلة بعد إثبات staging والتفويض.

`ACADEMIC-REPORTING-WORKFLOW-01` يبني لاحقًا موعدًا متوقعًا مؤرخًا وربط مفردات + دورة تقارير اليوم/الأسبوع/الشهر بنسخ وتواقيع الأدوار. يبدأ بعد ثبوت الجدول ومطابقة البيانات، ويستبقي سجلات تنفيذ الماضي عند تغيير النسخة.

**الثوابت:** صفر تغير في بيانات الإنتاج، صفر migration/deploy/publish، صفر تغيير `student_visible`، وصفر إنشاء حسابات أو سجلات وهمية في هذه المرحلة.
