# COUNCILS-ADMIN-SEED-PLANNING-01 — تقرير تخطيط بيانات التأسيس

- المرحلة: تخطيط فقط (Planning-only)
- النطاق: بوابة إدارة المجالس الأكاديمية (MVP)
- التنفيذ الفعلي: **لم يُنفَّذ أي SQL/Insert/Update/Delete/Seed/Import/Migration/Storage/Email/Cron/Deploy**
- الوضع الحالي: قاعدة المجالس مطبَّقة، RLS مفعّل، anon محذوف، الجداول فارغة، الواجهة قراءة فقط، أزرار الكتابة معطّلة.

---

## 1) الجداول المستهدفة لاحقاً (للـ Seed المحتمل)

| الجدول | الغرض في التأسيس | يُدرج في MVP؟ |
|---|---|---|
| `academic_councils` | إنشاء مجلس الكلية + مجالس الأقسام | نعم |
| `academic_council_members` | ربط الأعضاء بأدوارهم (chair/secretary/member/viewer) | نعم |
| `academic_council_meetings` | جدولة الاجتماعات | لا (خارج seed التأسيس) |
| `academic_council_agenda_items` | جدول الأعمال | لا |
| `academic_council_topics` | الموضوعات المرفوعة | لا |
| `academic_council_decisions` | القرارات | لا |
| `academic_council_minutes` | المحاضر | لا |

القاعدة: seed التأسيس يقتصر على **المجالس + عضوياتها فقط**. لا اجتماعات، لا موضوعات، لا قرارات، لا محاضر.

---

## 2) البيانات المطلوبة للتأسيس

### أ. مجلس الكلية (واحد)
- `council_type = 'college'`
- `department_id = NULL`
- `name = 'مجلس الكلية'`
- أعضاء بأدوار:
  - `chair` → العميد
  - `member` → نواب العميد (أكاديمي / طلاب)
  - `member` → رؤساء الأقسام الثلاثة
  - `secretary` → أمين الكلية (MISSING_INPUT — لا يوجد مستخدم مربوط حتى الآن)

### ب. مجالس الأقسام (ثلاثة)
لكل قسم فعّال (`departments.is_active = true`):

| القسم | department_id |
|---|---|
| قسم تكنولوجيا المعلومات | `ce485c67-5f7c-498d-b120-4b1130a86ae8` |
| قسم علوم الحاسوب | `11111111-1111-4111-8111-111111111111` |
| قسم نظم المعلومات الحاسوبية | `22222222-2222-4222-8222-222222222222` |

أعضاء كل مجلس قسم:
- `chair` → رئيس القسم
- `member` → أعضاء هيئة التدريس التابعين للقسم (بشرط تأكيد `department_id` في `faculty_profiles`)
- `secretary` → MISSING_INPUT (يحتاج قرار إداري لكل قسم)

## 3) مصادر البيانات الحالية المتاحة

| المصدر | الحالة | ملاحظات |
|---|---|---|
| `departments` | 3 أقسام فعّالة | جاهز |
| `faculty` (admin_position) | 6 قيادات مؤكدة: عميد + نائبان + 3 رؤساء أقسام | جاهز كمرجع اسمي فقط — **لا يوجد `user_id`** يربطها بحساب مصادَق |
| `faculty_profiles` | 34 عضو هيئة تدريس، جميعهم بـ `department_id` صحيح | جاهز، لكن يجب التحقق من `user_id` لكل قيادي قبل ربطه كـ chair/member |
| `user_roles` | 34 `faculty_member` + 1 `dean` + 2 `admin` + 2 `system_admin` | يوجد dean واحد فقط في user_roles — يجب التأكد أنه نفس العميد الظاهر في `faculty.admin_position` |
| `organizational_positions` | يحتوي على codes: `dean`, `vice_dean_academic`, `vice_dean_students`, `college_secretary`, `college_council` | مرجع تنظيمي فقط |
| `position_assignments` | **فارغ (0)** | لا يوجد ربط منصب↔مستخدم — نقص حرج |
| `staff_profiles` | 5 فقط | غير كافٍ لتغطية أمانة المجالس |

## 4) البيانات الناقصة — MISSING_INPUT

| # | البند | السبب |
|---|---|---|
| M-01 | `user_id` للعميد | `faculty.admin_position='عميد الكلية'` لا يحمل `user_id`؛ يوجد 1 dean في `user_roles` لكن لم يُتأكد أنه نفس الشخص |
| M-02 | `user_id` لكل من نائبَي العميد | لا يوجد ربط في `position_assignments` |
| M-03 | `user_id` لرؤساء الأقسام الثلاثة | نفس السبب |
| M-04 | أمين مجلس الكلية (secretary) | لا يوجد سجل مؤكد |
| M-05 | مقرر (secretary) لكل مجلس قسم | لا يوجد سجل مؤكد |
| M-06 | سياسة عضوية أعضاء هيئة التدريس في مجلس قسمهم: **جميعهم** أم **قائمة معتمدة**؟ | قرار إداري |
| M-07 | هل يشمل مجلس الكلية ممثلين إضافيين (طلاب/إداريين)؟ | قرار إداري |
| M-08 | نطاق البدء: **كل مجالس الأقسام** أم **IT فقط أولاً** كمرحلة تجريبية؟ | قرار إداري |

بدون M-01…M-05 لا يمكن ملء `academic_council_members.user_id` (وهو NOT NULL / FK إلى `auth.users`).

## 5) خيارا التنفيذ لاحقاً

### الخيار A — Seed الأدنى الآمن (موصى به كبداية)
- إدراج **مجلس الكلية فقط** (`academic_councils` صف واحد).
- **بدون أعضاء** الآن (نُدرج الأعضاء في مرحلة تالية بعد استلام user_ids المؤكدة).
- بدون اجتماعات/موضوعات/قرارات.
- الأثر: صفر مخاطر عضوية خاطئة. الواجهة تُظهر مجلس الكلية فعّالاً بدون أعضاء.
- يفتح الطريق لمرحلة `COUNCILS-ADMIN-SEED-MEMBERS-01` منفصلة عند اكتمال بيانات القيادات.

### الخيار B — Seed أولي أوسع
- إدراج مجلس الكلية + مجالس الأقسام الثلاثة (4 صفوف في `academic_councils`).
- إدراج chair لكل مجلس **فقط إذا** توفّرت user_ids مؤكدة (M-01, M-03).
- إدراج أعضاء مجالس الأقسام من `faculty_profiles` بشرط:
  - `user_id IS NOT NULL`
  - `department_id` مطابق
  - `status = 'active'`
- بدون secretary (تبقى MISSING_INPUT).
- بدون اجتماعات/موضوعات/قرارات.
- الأثر: تغطية أوسع لكنها تعتمد على توفر M-01…M-03.

### الخيار C (احتياطي) — Pilot قسم واحد
- مجلس الكلية + مجلس قسم IT فقط + chair + أعضاء IT المؤكدون.
- تجربة محدودة قبل توسيع باقي الأقسام.

## 6) المخاطر

| # | المخاطرة | الشدة | التخفيف |
|---|---|---|---|
| R-01 | إدخال عضوية بـ `user_id` خاطئ → منح شخص وصولاً لمجلس ليس له | High | لا نُدرج أي عضو بدون تأكيد ثنائي (اسم + user_id + department_id) |
| R-02 | فتح مجلس قسم لعضو من قسم آخر (cross-department leakage) | High | فلترة صارمة بـ `faculty_profiles.department_id = council.department_id` |
| R-03 | ربط dean/admin بأكثر من دور chair | Medium | فحص UNIQUE على (council_id, user_id) وسياسة role-per-user |
| R-04 | إدراج جميع الـ 34 faculty في مجالس أقسامهم دون قرار إداري | Medium | ننتظر M-06 قبل التوسع |
| R-05 | نقص secretary → قرارات لا تُوثَّق لاحقاً | Low (لا يؤثر على seed التأسيس) | يُحسم في مرحلة الكتابة |
| R-06 | تنفيذ seed قبل مراجعة بشرية للقيادات | High | كل صف عضوية يحتاج توقيع بشري في مرحلة `SEED-APPROVAL` |

---

## 7) هل يمكن تنفيذ seed آمن لاحقاً؟

**نعم، مشروطاً بـ:**
1. الخيار A قابل للتنفيذ فوراً بأمان تام (لا user_ids، لا مخاطر عضوية).
2. الخيار B/C يتطلب أولاً حل M-01…M-03 (تأكيد user_ids للعميد ورؤساء الأقسام).
3. لكل صف عضوية: توقيع بشري صريح قبل التنفيذ.

---

## 8) ما يحتاج موافقتك قبل التنفيذ

- **Q1**: أي خيار تعتمد؟ A (الأدنى) / B (الأوسع) / C (قسم IT فقط).
- **Q2**: هل عميد الكلية الظاهر في `faculty.admin_position` هو نفسه صاحب دور `dean` في `user_roles`؟ إن نعم — زوّدنا بالـ `user_id` أو أكّد المطابقة بالاسم.
- **Q3**: زوّدنا بـ `user_id` لكل من: نائب العميد الأكاديمي، نائب العميد للطلاب، رؤساء الأقسام الثلاثة.
- **Q4**: هل يُدخَل جميع أعضاء هيئة التدريس (34) تلقائياً في مجالس أقسامهم، أم قائمة معتمدة يدوياً؟
- **Q5**: من مقرر مجلس الكلية (secretary)؟ ومقرر كل مجلس قسم؟ (يمكن تركها فارغة الآن).
- **Q6**: هل نشمل ممثلين طلابيين/إداريين في مجلس الكلية ضمن seed التأسيس؟

## 9) ما لم يُنفَّذ (تأكيد صريح)

## 10) التوصية

**NEEDS INPUT** — التخطيط مكتمل، والخيار A جاهز للتنفيذ الفوري بأمان، لكن الخيارين B/C يحتاجان إجابات Q2…Q5 قبل المضي.

بمجرد استلام إجابات Q1 (اختيار الخيار) و Q2/Q3 (user_ids المؤكدة إن اختير B/C)، ننتقل إلى:

**COUNCILS-ADMIN-SEED-APPROVAL-01** ← مرحلة تجميع بيان seed نهائي للاعتماد قبل التنفيذ.
